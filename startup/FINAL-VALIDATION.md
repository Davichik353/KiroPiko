## Что наблюдалось отдельно

- Android preview запущен в эмуляторе API 36, подключён к Windows; статус Connected и передача одежды подтверждены. Это не тест физического телефона.
- Гардероб Android после исправлений просмотрен: единая высота карточек, линия стоп и пропорциональное отображение. Не все позы/одежда во всех состояниях проверены.
- Для плановой смены настроек исправлено ложное сообщение о потере связи. Регрессия проверена настоящими TLS-соединениями с тестовым сервером.
- Определение и основные команды настольной Яндекс Музыки ранее подтверждены пользователем. Случайный порядок/повтор через отдельный адаптер остаются без полной проверки.
- Ранее Google возвращал 404 для недоступной модели и 503 при высокой нагрузке. Модель по умолчанию обновлена; доступность облачного API в день показа не гарантируется.
- Groq добавлен отдельно: ключ, список активных чат-моделей, выбор и сохранение, маршрутизация телефона. HTTP-запрос с настоящим пользовательским ключом не выполнялся в этой проверке.

## Чего нельзя утверждать в заявке

Нет подтверждённого полного теста всех кнопок установленной версии, чистой Windows, нескольких физических мониторов/DPI, реальной отправки почты, микрофона/TTS, всех агентов и всех облачных моделей. Визуальный доступ к ПК через браузерный инструмент был заблокирован; обход не выполнялся. Документы заявки и GitHub не заменяют эти проверки.

## Перед демонстрацией

1. Закрыть личные документы и уведомления, скрыть API-ключи.
2. Запустить Windows и Android; убедиться в Connected.
3. Выбрать доступную модель, отправить короткий тестовый вопрос. При 503 сменить модель/провайдера; не обещать бесперебойную генерацию.
4. На тестовом проекте проверить отображение задачи и запрос разрешения. Не выполнять опасные команды ради демонстрации.
5. Показывать только успешно пройденные сценарии. Указать стадию «прототип» и происхождение от Coucou.

## Идеи для заявки

Основной приоритет — снизить ожидание агента и число переключений между окнами; сначала проверить это на 5–10 пилотных пользователях. Превращение снимка ошибки в подтверждаемый план, надёжная доставка запросов на телефон и единая диагностика подключений — план развития, не готовые функции.
